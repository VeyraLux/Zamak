# Zamak AI 编程闭环基准

这是一个离线、确定性的 AI 编程代理评测，不调用网络或模型。固定的“初始生成代码”和“修复补丁”用于衡量工具链本身：

- **首次通过率**：未修改候选直接运行 `zam check --json` 并通过检查。
- **修复轮数**：每轮只应用一个补丁，重新检查；记录是否修复成功。当前脚本只模拟一轮补丁，不代表多轮代理修复。
- **诊断匹配率**：首轮诊断 code 与案例期望值的匹配比例。
- **协议检查**：核对 JSON 结构、退出码与 `ok` 一致性，以及失败时 stderr 非空。路径记录仅作参考，因为路径显示可能受平台影响。
- **构建与运行**：修复后的案例执行 `build --json`，记录首次/热构建时间、缓存 MISS/HIT 和可执行文件大小；运行产物，统一换行后精确核对标准输出。
- **反馈延迟**：记录每次 `zam check --json` 样本，分别报告首次耗时和后续样本中位数。首次耗时不等于冷操作系统缓存，结果不代表模型生成质量。

运行：

```powershell
pwsh -File bench/ai/run.ps1 -ZamPath .\zam\target\debug\zam.exe -LatencyRepeats 3
```

案例固定写在 `cases.json`：一个合法对照（不改也能通过检查并正确运行）、八个需要一轮补丁的错误案例、一个不支持能力的负向对照（应被拒绝且不产出可执行文件）。错误案例覆盖词法（`ZM100`）、类型（`ZM200`）、所有权移动（`ZM301`）、修改不可变绑定（`ZM302`）、数组越界（`ZM406`）、缺少显式借用（`ZM425`）、缺少字符串返回值（`ZM510`）和字面量超出 `i64`（`ZM600`）。每个案例的期望诊断 code、补丁和最终输出都在文件里，便于审阅；补丁是脚本里的固定替换，不依赖模型。

结果写入被忽略的 `results/ai-bench-*/report.json`，每个案例还保留原始 `*.stdout.txt` / `*.stderr.txt` 捕获。基准固定记录操作系统、工具版本、命令、诊断 code/category 和 stdout/stderr 分离状态。
