# 常见算法性能优化

目标是在明确列出的算法、输入和工具链下，逐项改善 Zamak 相对 Rust release 与 Go 的运行性能。没有有限基准能够证明“所有常见算法”均领先；未测量的算法不在结论范围内，记录未达标项目。

## 工具链

测试环境已验证 Rust 1.96.0、Go 1.26.4、MinGW GCC 16.1.0 和 MSVC Build Tools 可以编译并运行测试程序。Windows 默认使用 MSVC；设置 `CC=gcc` 可使用 GNU 后端。编译器身份、编译选项与生成 C 均参与原生缓存键。

## 当前实现

GNU 风格后端采用 C11、`-O2 -funroll-loops`；MSVC 保持 `/O2`。循环展开已通过本机 GCC/MSVC 双后端回归及七项性能验收，尚未单独验证 Clang 的性能收益。GCC/Clang 通过 `__builtin_add_overflow`、`__builtin_sub_overflow`、`__builtin_mul_overflow` 实现有符号整数检查，其他编译器保留可移植检查。程序中的溢出、除零、`INT64_MIN / -1` 和数组越界仍然报错。除法或取余的右侧若是既非 `0` 也非 `-1` 的整数字面量，后端直接生成 C 运算；这些除数对任意 `i64` 分子都不会触发上述错误，操作数仍按原顺序求值。

除法/取余还在 GCC/Clang 下加入操作数均落在 `0..=UINT32_MAX` 时的无符号 32 位快路径；负数或更大值走原有有符号 64 位路径，除零及极小值错误先检查。跨符号与位宽边界的变量除法测试已在两个后端通过。除法相关复测结果如下，单位为毫秒/批；每个配置五个正式样本，精确校验和一致。

## 复现

在仓库根目录使用已有工具链执行：

```powershell
$env:CC = 'gcc'
pwsh -File tools/bench-common.ps1 -CCompiler gcc
```

脚本先构建 release 编译器，再分别编译对照程序。结果保存到本地 `results/tutorial-perf-*/results.json`。不要与构建、测试或其他耗 CPU 的任务并行运行。Windows 默认后端与 GNU 后端的数字分别记录，不能混用为同一次比较。

## 比较方法

主对照采用 Rust `opt-level=3`、关闭溢出检查，以及 Go 默认优化构建。带溢出检查的 Rust 单独记录，用于分析语义差异。C 编译器与选项单独记录。各语言执行相同算法与种子输入，核对精确校验和；构建时间排除在程序耗时之外。

扩展基准覆盖最大公约数、素数计数、迭代斐波那契、64 项数组插入排序、64 项数组二分查找、整数算术求和、模递推。Zamak、C、Python、Rust release、带溢出检查 Rust 与 Go 的七项种子循环校验和全部一致（42 组）；正式计时使用五个样本，每次至少 0.5 秒，按固定随机顺序交错执行各语言。Zamak 的重复次数写入生成驱动程序，其他语言从命令行读取，因此循环边界可见性并不完全一致；算术求和可能被优化为闭式表达式，这属于主对照的合法优化；本基准比较源程序结果与优化后的耗时，不要求每种语言执行相同数量的机器指令。二分查找各个种子的结果均为 2080，因此精确校验和验证结果一致，不能单独证明循环未被优化消除。首轮结果如下，单位为毫秒/批。五个样本的中位数仅描述本机本次运行；接近的差异需要复测确认。
