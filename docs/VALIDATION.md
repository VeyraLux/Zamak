# 案例与性能验证

本文记录 Zamak 0.1.0 的验证范围与可复现方法。测试通过只表示所列输入与路径符合预期，不代表完整语言或生产环境验收。

## 功能案例

运行：

```text
cargo test --manifest-path zam/Cargo.toml --locked --test common_cases
cargo test --manifest-path zam/Cargo.toml --locked --test tutorial
zam run examples/tutorial_cases/main.zm
```

[案例源码](../examples/tutorial_cases/main.zm)覆盖阶乘、迭代斐波那契、最大公约数与最小公倍数、素数判断、定长数组冒泡排序与搜索，以及借用字符串插值和 UTF-8 长度。

[功能测试](../zam/tests/common_cases.rs)断言原生程序的完整输出，另覆盖编译期拒绝和运行期整数溢出。[教程测试](../zam/tests/tutorial.rs)提取教程中的 Zamak 代码块并执行 `zam check`；该测试不执行每一段程序，也不验证每一项预期输出。

这些案例使用固定输入。尚未实现的 stdin、文件、网络、浮点数和动态数组不在通过范围内。

## 首轮三算法性能方法

以下记录保留首轮预览验收的方法与结果；后续扩展基准的方法和结果见[性能优化记录](PERFORMANCE.md)。

Windows 上需要 Python 3、Rust stable 和 MSVC C++ 工具链。在仓库根目录执行：

```powershell
pwsh -File tools/bench-common.ps1
```

运行器构建 release 编译器，生成各语言驱动程序，校准重复次数，并将命令、构建时间、样本、输出及工具版本记录到 `results/`。实现见[运行脚本](../tools/bench-common.ps1)与[内核生成器](../tools/common-kernel.py)。结果目录为本地产物，不随仓库分发。

每个配置测量三个新进程，取中位数；时间包含进程启动与输出，以每批算法工作量归一化。输入种子循环为 0–7，并核对精确校验和。构建时间单独记录。预设筛查标准为 Zamak 中位时间不超过无检查 C 的三倍；带等价整数检查的 C 用于解释差异，不替换验收标准。

## 当前测量结果

环境：Windows 10 19045、MSVC 19.51.36247、Rust 1.96、Python 3.11.9。循环不变边界优化后重跑，共 45 个正式计时样本，校验和全部一致；每个样本不少于运行器要求的 200 ms。表中单位为毫秒/批。

| 算法 | Zamak | C | 带等价检查的 C | Rust | Python | Zamak/C | 三倍筛查 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 最大公约数 | 3.2021 | 2.9806 | 3.0815 | 1.3291 | 44.3360 | 1.07× | 通过 |
| 素数计数 | 1.8673 | 3.0111 | 1.8143 | 0.9961 | 42.5411 | 0.62× | 通过 |
| 斐波那契 | 0.8277 | 0.3754 | 1.3998 | 0.4681 | 57.3098 | 2.20× | 通过 |

这三个算法均通过预设的三倍筛查。优化前斐波那契为 1.5299 ms/批、约为无检查 C 的 4.17 倍，未通过；保持原算法与输入不变，循环不变边界优化后为 0.8277 ms/批，耗时减少约 46%。带检查 C 没有应用同一边界提升，因此该列用于解释检查成本，不表示相同优化水平。

这是单机微基准。各语言采用不同重复次数后按同一工作量归一化；Zamak 驱动使用编译期重复次数，其他驱动接受运行参数。没有同机历史基线，因此不能判断是否发生版本回归，也不能从三个算法推断通用性能。

## 预览包验证

本地 Windows 开发包已通过 ZIP 生成、重新解压、包内编译器执行 `new` / `check` / `build` / `run` / `fmt`，以及生成程序独立执行的检查。随包算法案例的完整输出也纳入解压后验证。该结果与算法性能筛查共同构成本地 Windows 预览版的验收范围；其他平台与远端 CI 状态需单独确认。

加法检查曾试用无符号符号位检测，斐波那契中位时间只改善约 3.4%，且素数案例耗时增加，因此已撤回。回归测试保留了正负溢出和合法极值加法断言。该试验没有保留；后续 GCC/Clang 溢出 intrinsic、除法位宽优化和整数区间分析见[性能优化记录](PERFORMANCE.md)。

优化前的生成代码和 MSVC 汇编显示，算术辅助函数已被内联，表达式临时变量已消除。内层循环每轮仍重新执行边界表达式 `(i + seed) % 40` 的检查与取模。原生后端现在仅提升比较条件右侧的纯标量算术表达式：左侧必须是变量或字面量，右侧引用的变量不能被循环体（含嵌套分支与循环）修改；函数调用、数组访问、字段访问和短路条件不提升。边界仍在首次条件判断时求值，空循环也保留算术错误。回归测试覆盖可变边界、嵌套赋值、`continue`/`break`、函数调用、短路条件及错误求值顺序。
