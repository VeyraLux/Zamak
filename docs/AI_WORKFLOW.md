# AI 编程工作流

用结构化诊断定位错误，修改后重新检查、构建并运行：

```text
生成代码 → zam check --json → 读取 code/category/location/suggestion
→ 做最小修改 → zam fmt → 再 check → build → run
```

## 诊断契约

`check --json` 和 `build --json` 的 `diagnostics` 保留人类可读的 `message`，并提供稳定的 `code`、`category`、`file`、`line`、`column`、`function` 与可选 `suggestion`。AI 工具应优先依赖 `code` 和位置，不要用完整 message 做唯一分支条件。`zam/tests/diagnostics.rs` 用真实源码逐个断言这里的 code、category 和非空 suggestion，避免分类只在单元测试里成立。

常见代码包括：

- `ZM100`：词法字符错误；
- `ZM101`：字符串转义不支持；
- `ZM110`：语法结构错误；
- `ZM200`：类型不匹配；
- `ZM201`：名称未定义（变量、函数、结构体或类型名）；
- `ZM202`：结构体字段未定义；
- `ZM203`：缺少标准库导入（`use std/<namespace>`）；
- `ZM204`：重复声明（导入、字段、函数或初始化项）；
- `ZM301`：移动后使用；
- `ZM302`：修改不可变绑定；
- `ZM406`：数组边界错误；
- `ZM421`：借用冲突；
- `ZM422`：借用逃逸；
- `ZM423`：借用类型不匹配；
- `ZM424`：不可变值的可变借用；
- `ZM425`：需要显式借用（缺少 `&` 或 `&mut`）；
- `ZM500`：未处理的可失败调用；
- `ZM509`：错误类型不是 `string`；
- `ZM510`：缺失返回值；
- `ZM600`：整数算术安全错误，包括字面量超出 `i64` 范围；
- `ZM900`：暂不支持的能力；
- `ZM999`：尚未归类的工具错误，AI 应保留完整 `message` 并提交最小复现。

## 模板

使用 `zam new demo --template ai` 生成带 `AI.md` 的项目。每轮只做一个局部修复；修复后重新运行 `check --json`，通过后再构建和执行。模板明确列出当前不支持的浮点、文件/网络 I/O、泛型、枚举、闭包、线程和 FFI，减少模型凭经验猜测语法的失败。

## 离线评测

`bench/ai/` 提供固定候选与固定补丁，不需要模型或网络。当前 23 个案例覆盖合法对照（单文件与多模块各一）、词法、类型、名称解析、缺少标准库导入、重复声明、所有权移动、修改不可变绑定、数组越界、借用冲突与借用逃逸、错误值处理、缺少字符串返回值、字面量超出 `i64`、未知结构体字段，以及一个应被拒绝的不支持能力负向对照。多模块案例用 `files` 字段给出多文件项目，脚本生成 `zam.toml` 与 `src/` 并以项目目录为检查/构建目标，覆盖跨模块 `use`、`pub fn` 与项目模式诊断。评测记录首次检查通过率、一轮固定补丁的修复结果、每次 `check --json` 延迟、首次与缓存命中构建时间及产物大小。报告用 `zamak_backend` 记录本次所用的 C 后端（取 `CC` 环境变量，未设置即 Windows 默认 MSVC），使这些延迟数字自述后端，不与其它后端的批次混排。通过检查的案例还要构建、执行并核对输出；不支持的能力作为应被拒绝的对照例单独统计。它衡量工具链的反馈与验证流程，不代表任意模型的生成能力。
